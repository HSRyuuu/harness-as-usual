# v0.2.0 — Three Peer Work Units

**Date:** 2026-07-25 · **Previous:** 0.1.2 · **Commits:** `6c05db3`..`ed03a28`

> Reconstructed from git history on 2026-08-25.

**Breaking, deliberately.** 0.1.x had one pipeline with branches bolted on:
`find-cause` for investigation and `direct-execute` for settled work were
special cases of the topic flow, each with its own record helper and its own
rules file. v2 makes them peers.

## The Model

Three work units, no primary:

| Unit | The work is | Ends with |
| --- | --- | --- |
| `topic` | development that needs the requirements agreed first | code change + `report.md` |
| `direct-work` | development where what to do is already settled | code change + verification record |
| `issue` | confirming a cause or direction without changing code | `conclusion.md` |

## What Was Rebuilt

- **One record layer.** `topic-log.py` and `journal-log.py` collapse into
  `as-usual-record.py` over the `as-usual.record.v1` schema — one append-only
  `audit.jsonl` per unit, one set of gates, one vocabulary.
- **Seven rules files become three**: `core-rules.md`, `safety-rules.md`,
  `record-commands.md`. A rule has one owner; other files may reference it but
  never restate its conditions.
- **The skill layer is rebuilt around three unit owners** — `run-topic`,
  `run-direct-work`, `run-issue` — which declare their pipeline as an
  application matrix. Step skills are shared and never branch on the calling
  unit.
- **Templates cut down** to what the work actually needs. `topic.md`,
  `question-cN.md`, `problem.md`, and `code-review-report.md` are gone;
  `contexts.md` becomes the one file every unit keeps.
- **One entry point.** `using-as-usual` classifies with a two-question tree and
  hands off. `start-work`, `hand-off`, `find-cause`, and `direct-execute`
  disappear as entry points.

Also fixed here: the sealed-record vs `git-action` conflict, and the release
skill's own verification commands.

## Breaking Changes

- **Pre-v2 work folders are not resume targets.** `topic.md`, `journal.jsonl`,
  and `question-cN.md` layouts are not read by the v2 helper.
- Every removed skill, template, phase name, and event kind stays removed —
  reintroducing one is listed as an anti-pattern in `AGENTS.md`.

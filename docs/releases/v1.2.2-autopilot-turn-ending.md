# v1.2.2 — Autopilot turn ending

Opus 5.5 프롬프팅 가이드에 맞춰 autopilot이 일을 남긴 채 턴을 끝내지 않도록 했고,
런타임 문서에서 다른 파일이 소유한 규칙을 다시 적은 문장을 참조로 바꿨다. 직전에
버전 올림 없이 push된 `4cc41e6`(요청 경계와 증상 연결 근거)도 이 릴리스로 배포된다.

## 변경 사항

- `core-rules.md` §10에 "Ending a turn"을 추가했다. autopilot에서 작업이 남아 있고
  멈출 조건이 없으면, 도구 호출 없이 끝나는 턴은 완료가 아니라 보고다. 다음 단계를
  예고만 하고 끝내기, "원하시면 계속"으로 기다리기, 막히지 않는 결정 목록 넘기기,
  마일스톤 보고로 멈추기를 `NEVER:` 목록으로 금지한다.
- `using-as-usual`, `gathering-context`, `run-issue`에서 `core-rules.md`·`safety-rules.md`
  조건을 다시 적은 문장을 참조로 바꿨다. 두 skill의 Anti-Patterns 절은 본문과 겹쳐 뺐다.
- issue에서 git 질문을 기본으로 하지 않는 규칙을 `finalize`의 unit 분기에서
  `run-issue` 매트릭스로 옮겼다. 동작은 같다.
- `4cc41e6`: 요청의 정지 지점 기록, 실행 승인이 덮는 계획의 명시, 증거 출처(profile·환경·
  역할) 보존, 국소 결함의 테스트 PASS가 제보 증상을 입증하지 않는다는 규칙.

## 사용자가 달리 할 일

플러그인을 업데이트한 뒤 새 세션을 시작한다. 기록 마이그레이션은 없다.

## 검증 범위

record 테스트 156개, manifest·hook·미러·공개 경로·워크플로 일관성 검증을 통과했다.
합성 저장소 6과제의 전후 비교(Claude, opus-5-5, 과제당 1–3회)에서 판정과 비용 차이는
없었다. autopilot 규칙의 효과는 짧은 과제에서 드러나지 않아 INCONCLUSIVE다.

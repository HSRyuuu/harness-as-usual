# v2.1.0 — Drop legacy unit folders

v2.0.0에서 "그대로 재개된다"고 했던 `topic`·`direct-work`·`issue`·`inbox` 폴더 지원을 없앴다.
v2.0.0 노트의 해당 항목(레거시 재개, 두 가지 예외)은 이 릴리스부터 맞지 않는다.

## 변경 사항

- 레거시 단위 폴더는 재개 대상이 아니다. `add`·`link`가 거부하고(`link`는 양쪽을 먼저 확인해
  한쪽만 연결된 채로 남지 않는다), `validate`는 unit을 잘못된 값으로 보고한다.
  `using-as-usual`은 그런 폴더를 pre-v2 기록처럼 알리고, 옛 파일을 입력으로 새 작업을 제안한다.
- gate가 unit 라벨로 분기하는 곳이 없어졌다. 옛 issue의 `execution` 승인을 재현 스크립트로
  보던 예외와, 옛 topic에 `verification.md`를 늘 요구하던 예외를 지웠다.
  - 이유: 옛 issue 폴더를 재개해 같은 폴더에서 구현까지 이어가면 plan 리뷰(rule 7)와
    검증 증거(rule 3)가 둘 다 건너뛰어졌다.
- 옛 phase `investigating`·`concluding`, `lifecycle:unit-selected`, `contexts.md`의
  프론트매터 이전 `## Work Unit` 섹션 읽기를 어휘와 코드에서 지웠다.
- 템플릿의 `unit:` 칸은 `work`로 고정했다.
- 다이어그램 02~07을 단일 `work` 기준으로 다시 그리고 README에 다시 넣었다
  (`02-one-door`, `03-pipeline`, `04-investigate`, `05-work-folder`, `06-skills`,
  `07-record-layer`). 01의 rule 6 문구를 현재 규칙으로 고치고, 제거된 장기 memory를 가리키던
  두 항목을 바꿨다.
- manifest 설명을 단일 work 기준으로 고치고, `marketplace.json` 버전과 README 배지를 맞췄다.

## 사용자가 달리 할 일

- 플러그인을 업데이트하고 새 세션을 시작한다.
- 진행 중인 `topic/`·`direct-work/`·`issue/`·`inbox/` 폴더가 있으면 새 AsUsual 작업을
  시작하고, 옛 폴더의 파일을 입력으로 읽게 한다. 옛 폴더에는 더 이상 기록을 추가할 수 없다.

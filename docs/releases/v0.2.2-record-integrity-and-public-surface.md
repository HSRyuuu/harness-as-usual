# v0.2.2 — Record Integrity And The Public Surface

**Date:** 2026-08-07 · **Previous:** 0.2.1 · **Commits:** `fe0a394`..`9e7f50e`

> Reconstructed from git history on 2026-08-25.

Consistency work across the whole surface after v2 settled, plus the record
gaps a harness review found.

## Record Layer

- **The record-integrity gaps the harness review found** are closed.
- **Vocabulary that no gate enforces is dropped.** An event kind exists only
  when a script gate uses it; anything else belongs in `summary` or `--data`.
  This became a convention.
- **The push approval rule gets a single owner** instead of being restated in
  several places.
- **Classification, priority, and folder creation are realigned** so the entry
  skill cannot recommend one unit and create another.
- **The delegation and review contracts are aligned** with each other.

## Hook

The session hook now fires on **resume**, not just on a fresh session — a
resumed session was starting without the capability announcement.

## Long-Term Memory Moves Out Of `.as-usual/`

Memory relocates from `.as-usual/memory` to `docs/memory`. The reasoning that
motivated the move is also what killed the surface in 0.3.0: it was the one
thing writing outside the work unit.

## Documentation

- The README is rewritten around the three work units, with per-unit pipeline
  diagrams at readable type.
- The public surface is caught up with the record gates.
- `contexts.md` headings put the entry content before the timestamp.
- The marketplace description is synced with the plugin manifest.

## Also In This Release

- **An opt-in auto mode** ships as a fourth runtime rules file. It is reverted in
  0.2.3.
- `gathering-context` stops answering what is the user's to decide.

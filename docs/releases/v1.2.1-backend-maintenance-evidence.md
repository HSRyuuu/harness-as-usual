# v1.2.1 — Backend maintenance evidence

기존 서비스의 로직을 이해하고 수정·확장할 때, 탐색 근거가 계획과 검증까지 이어지도록
보강했다. 세 작업 단위와 기록 스키마, 승인 절차는 유지한다.

## 변경 사항

- 탐색·계획에 현재 호출 흐름, 영향받는 소비자, 참고 구현의 재사용 지점과 차이,
  보존 동작, 테스트 진입점과 근거 checkout을 연결한다.
- 요구사항에서 변경할 동작과 유지할 동작을 구분한다. 이번 변경으로 발생한 회귀는
  호출자 파일이 수정되지 않았더라도 리뷰 대상이다.
- 이전 결정은 report 유무만으로 판단하지 않는다. 관련 작업의 상태와 contexts,
  requirements·plan·conclusion·report 중 결정이 담긴 파일을 읽고 취소·대체를 구분한다.
- 완료 전 검증 당시와 현재 상태를 비교한다. 관련 변경으로 이전 PASS가 무효가 됐다면
  새 INCONCLUSIVE를 기록하고 해당 검증을 다시 실행한다. 변경 감지는 에이전트가 하며,
  helper가 소스 변경을 자동 감지하는 기능이 추가된 것은 아니다.
- 기록 이력의 회귀 검사와 [백엔드 작업 평가 절차](../BACKEND-MAINTENANCE-EVALUATION.md)를
  추가했다. 기존 상태 전환 설명과 삭제된 검증 스킬의 등록 항목도 정리했다.

## 사용자가 달리 할 일

플러그인을 업데이트한 뒤 Claude Code와 Codex에서 새 세션을 시작한다. 기존 작업 기록을
마이그레이션할 필요는 없다. 완료할 때 현재 상태에 맞는 검증 근거를 남긴다.

## 검증 범위

record 테스트 156개와 CLI 정상·거부 검사 17개, manifest·hook·미러·공개 경로·워크플로
일관성을 검증했다. 합성 기록의 제한된 모델 검색 검사도 수행했으나, 실제 비공개 백엔드
과제의 12회 전후 비교는 미완료다. 이 릴리스는 실무 성공률 향상을 입증했다고 주장하지 않는다.

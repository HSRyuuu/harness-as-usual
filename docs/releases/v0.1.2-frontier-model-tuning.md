# v0.1.2 — Frontier-Model Tuning

**Date:** 2026-07-21 · **Previous:** 0.1.1 · **Commits:** `9c20356`..`6c05db3`

> Reconstructed from git history on 2026-08-25.

The release where the record/judgment split became explicit. Ceremony that
existed to compensate for a weak model was cut; gates that exist for permission
and evidence were kept.

## The Split

Loosened — these are the model's judgment:

- **Routing discretion** goes to the agent, gated on risk rather than task size.
- **TDD relaxes to test-required**, and the exception-approval ceremony around it
  is dropped.
- **Requirements clarification defaults to batched chat**; the question-file
  cycle becomes the exception, not the path.
- **Task requirements and quality reviews merge** into one pass.
- **Plan cross-cutting sections become conditional**, and `writing-plan` slims
  accordingly.
- Inline work skipping task review becomes an explicit design decision rather
  than an omission.

Kept and tightened:

- `conclusion.md` is required before an issue can conclude.
- Cause-unknown bugs route to `find-cause`, and issue self-improvement runs
  before closure.

## Rules Files Get Single Owners

`core-workflow.md` shrinks to an entry point and the rules move to owner files —
routing, logging, completion, and shared safety rules each get exactly one home,
registered in the verification skills and docs. Seven files at the end of this
release; 0.2.0 collapses them to three.

## Also In This Release

- **`direct-execute`** runtime skill: work already settled enough to skip
  requirements, still recorded.
- **Execution-mode choice** presented at plan approval.
- **`publish-as-usual`** release skill registered in the maintainer docs.
- Marketplace installation guides updated for the identity switch in 0.1.1.

# v2.0.0 — Single work unit

`topic`, `direct-work`, `issue` 세 작업 단위를 `work` 하나로 합쳤다. 진입할 때 단위를
고르지 않고 요청 범위(조사만 / 계획까지 / 실행)만 기록한다. 기록 계층(스크립트 전용
audit, 고위험 새 승인, 검증 증거, 명시적 git 선택, 신뢰 경계, 실행 승인 전 plan 리뷰)은
그대로다. 버전 올림 없이 push된 `a2e248b`(사용자 지시 plan 변경, 테스트 먼저 기본값,
프로젝트 plan 위치)도 이 릴리스로 배포된다.

## 변경 사항

- 새 기록은 `.as-usual/work/<slug>/`. 4개 선택지 분류, `inbox`, `move`, `lifecycle:unit-selected`,
  `status`의 `moveAllowed`를 없앴다. 조사로 원인을 확정한 뒤 같은 폴더에서 구현으로 이어간다.
  별개 후속 작업만 새 폴더와 `link`를 쓴다.
- `run-topic`·`run-direct-work`·`run-issue` → `run-work` 하나(행마다 적용 조건이 있는 매트릭스).
  조사 루프는 새 step skill `investigate`(phase `investigate`)로 옮겼다. `requirements.md`는
  모호하거나 위험한 일에만 쓴다.
- gate는 단위 대신 기록 내용으로 판단한다.
  - 모든 `execution` 승인은 plan 리뷰가 필요하다.
  - finalize: 승인된 실행이 있으면 검증 기록, `requirements.md`가 있으면 `verification.md`까지.
    `conclusion.md`가 있으면 confirmed 항목. 둘 다 없으면 "nothing to finalize"로 거부.
  - 새 승인 action `reproduction`: 조사 중 재현 스크립트용. 사용자 승인만, plan 리뷰 불필요.
- git worktree 안에서는 main checkout root에 기록을 둔다. worktree를 지워도 남는다.
- (`a2e248b`) 실행 중 사용자가 직접 지시한 변경은 그 지시를 결정·실행 승인으로 기록하고
  plan의 `## Changes During Execution`에 남긴다. 동작 변경은 테스트 먼저가 기본이다.
  프로젝트에 plan 규칙이 있으면 그 위치에 쓰고 작업 폴더에는 포인터만 둔다.

## 사용자가 달리 할 일

- 플러그인을 업데이트하고 새 세션을 시작한다.
- "AsUsual topic으로" 대신 "AsUsual로 진행해줘"라고 하면 된다. 범위는 "계획까지만",
  "조사만"처럼 말한다.
- 기존 `topic/`·`direct-work/`·`issue/`·`inbox/` 폴더는 그대로 재개된다. 마이그레이션은 없다.
  예외 두 가지: 옛 issue의 `execution` 승인은 재현 스크립트로 해석하고, 옛 topic은 종료에
  `verification.md`가 계속 필요하다.
- `as-usual-record.py move`와 `init --unit topic|direct-work|issue|inbox`는 더 이상 없다.

# v1.2.0 — Records That Correct Themselves

**Date:** 2026-08-31 · **Previous:** 1.1.0 (2026-08-27)

This release came out of reading AsUsual's own output. Eighteen work units from a
real project — nine `topic`, five `direct-work`, four `issue`, 348 audit events —
were read against the contract, and the finding was narrow enough to state in one
sentence:

**The record layer enforces writing and does not enforce re-writing.**

Every durable context problem found in that corpus happened on a surface with no
way to say "this was reversed": a `decision` event, a sealed artifact, a folder
that had already closed. The layers that *do* have that mechanism — the
`contexts.md` middle band, `verification --resolves` — worked.

No new event kind, phase, approval action, or vocabulary value. The vocabulary
count is unchanged, deliberately: the first draft of this work proposed a
`--supersedes` flag, and building it turned out to be unnecessary.

---

# Part 1 — The Mechanism That Was Already There

`status-change --target <seq> --to cancelled --reason "…"` has always accepted a
`decision`. `REASONING_KINDS` in `constants.py` lists `decision`, `hypothesis`,
`review`, `work`, `note`, and the gate has never restricted it further.

In 348 recorded events, it was used four times — all four inside `issue` folders,
all four on hypotheses. Not once on a `decision`, across 82 of them. In the one
unit where a maintainer needed exactly this, they invented
`--data supersedes=<seq>` by hand rather than use the flag that existed.

That is a documentation defect, not a missing feature. The contract described
`status-change` only where it described investigations, so it read as an `issue`
move.

## What changed

`core-rules.md` §5 now says it plainly: `status-change` retracts reasoning, and a
`decision` is reasoning like any other. `record-commands.md` names the accepted
target kinds in the `status-change` row.

`status --json` was the other half of the problem. It reported
`"cancelled": [2]` — a bare seq. Knowing *what* was reversed meant opening
`audit.jsonl`. It now carries the target's summary and the reason:

```json
"cancelled": [{"seq": 2, "by": 3, "summary": "join the promo key with a pipe",
               "why": "Tomcat rejects a pipe in the path with a 400"}]
```

## The correlation that decided the design

In one unit, three decisions were reversed. The two the maintainer marked with
their hand-rolled `supersedes` also got a full sweep of `contexts.md`,
`requirements.md`, and `plan.md`. The one that got no marker left four documents
asserting a position the shipped code contradicts. Three for three.

Marking the reversal and propagating it turned out to be the same act.

# Part 2 — Corrections That Reach The Reader

A sealed record accepts nothing but links. So a unit that closes cannot mark its
own decision superseded, and every cross-folder correction has exactly one
channel: `link`.

`link` wrote only `audit.jsonl`.

In the corpus that produced two symptoms. Four `linked` events between one pair of
units, and neither `contexts.md` mentioning the other. And a `contexts.md` link
with no backing event, written by hand. The two surfaces had zero overlap for that
pair.

Worse, the contract contradicted itself: §7 required a link after closing, and §3
declared every artifact final at close — including the file the link belongs in.

## What changed

- **`link` writes both documents.** One invocation appends to each side's
  `## Linked Work` band, creating it when the document does not have one.
- **`## Linked Work` is named as a post-seal band**, alongside `verification.md`.
  The contradiction is gone from the text.
- **`--summary` is where a supersession goes.** `record-commands.md` says to state
  what the other unit supersedes, so a reader landing on the stale decision meets
  the correction on the same page.
- **`cancelled` marks the document.** The event now prepends a notice under
  `# Context`, above every band:

  ```markdown
  > **CANCELLED 2026-08-31 19:14:53 (#3)** — premise was false
  >
  > already cached upstream
  ```

  A cancelled unit whose only trace was one JSONL line went on reading as live
  work. One in the corpus had 99 lines of documents doing exactly that.

Both writers refuse rather than guess. A document with no frontmatter and no
`# Context` title is left untouched and the command says which file to fix by
hand — the event is already recorded either way.

# Part 3 — Derived State That Tells The Truth

Three defects, all in what `status` and `validate` report about records that
already exist.

## Phantom blockers

`open_blockers()` kept a resolving blocker open, on the reasoning that "A is
cleared but B now blocks us" is one event and B has to stay visible. That is
correct and it is why 1.0.0 added it (F4). But it meant *every* clean resolution
left a phantom, closable only by another blocker, which would then be open in its
turn. A finalized, pushed unit reported two open blockers whose summaries both
began "resolved —".

The distinction was already in the data. Across twelve recorded blockers, all
three that carried `--resolves` were `--status success` and were plain
resolutions; both entries that were genuinely still blocking were `warning` or
`error`.

So `--status` decides. `--resolves` plus `success` means it closed something and
introduced nothing, and it stops counting as open. `warning` or `error` stays
visible. F4's regression test kept every assertion and needed only its fixture
changed to say out loud that something still blocked.

**The caveat, stated because the default hides it:** `--status` defaults to
`success`. Recording a compound blocker without `--status error` now hides it.
The contract says so in two places and the tests pin both sides, but there is no
gate.

## A headline `PASS` over an open gap

`status --json` returned `"verification": {"verdict": "PASS"}` next to
`"openVerifications": [{"seq": 11, "verdict": "INCONCLUSIVE"}]` — the exact state
`templates/verification.md` says cannot exist.

The standing verdict now reads `INCONCLUSIVE` while any gap is open and names
what downgraded it. The newest event is still there as `latestVerification`. The
two answer different questions and both are reported.

## An audit that could not see its own blind spot

The append gates run when a unit closes. A record sealed before a gate existed
audits clean forever. Four such units are in real use — sealed over open
`INCONCLUSIVE` verdicts, or as a `topic` with no `verification.md`, hours before
the gate that would refuse them landed.

`validate` now re-judges sealed units against today's finalize gate and reports
what it would refuse. As `warning:` lines that **never reach the exit code**:
reaching backwards to fail them would break the promise retired vocabulary
already keeps — an entry legal when written stays legal.

# Part 4 — Smaller Things

- **`init` writes no placeholders.** A new `contexts.md` is frontmatter,
  `# Context`, and the request. `core-rules.md` §3 already forbade filling a
  section with a placeholder, and the helper was the one doing it. Five units in
  the corpus sealed with the skeleton untouched, three of them claiming
  `Linked Work: _None._` while their own record held link events.
- **`init` adopts an orphaned artifact folder.** `INIT_BLOCKING_FILES` is now the
  record files only. A folder holding `plan.md` and no record was refused as
  "already a work record" — false, and it left the only recovery as deleting the
  document. One such folder exists in the corpus, and it is why a shipped API
  contract reversal has no record anywhere.
- **Narrowed criteria are named.** `templates/verification.md` asks for the
  criterion quoted from `requirements.md`, and says a criterion narrowed until it
  passes is `INCONCLUSIVE` for the criterion as written — the §6 substitution made
  one step earlier than a softer verdict word. `core-rules.md` §6 adds the same
  about filing an unverified criterion as a `blocker`.
- **`conclusion.md` states a direction, not a task list.** One investigation
  shipped a six-task plan naming five files; the follow-up overruled its central
  choice within the hour, and the sealed document had no way to say so.
- **Deliverables for other people move out.** §3 says a document written for an
  audience outside the unit belongs where that audience looks, linked from
  `report.md`. In the corpus three API specs lived inside work folders, kept being
  edited 27 hours after sealing, and were then copied wholesale — 1,276 lines
  carrying 39 lines of difference.
- **Skills.** `gathering-context` checks whether another unit already decided a
  surface before recommending one. `using-as-usual` marks stale `open` units in
  the resume list and reports folders with artifacts and no `audit.jsonl`.
  `run-topic` and `run-direct-work` close a unit whose premise dissolved instead
  of leaving it open; `run-issue` concludes normally, because "nothing is wrong"
  is the deliverable an issue exists to produce. `finalize` retracts reversed
  decisions before sealing, while the record still takes events.

# What To Do Differently

**Users**

- When a decision you agreed to gets reversed, say so on the record:
  `add --kind status-change --target <seq> --to cancelled --reason "<what is now
  true>"`, and edit the `contexts.md` Decisions entry so it reads as the current
  agreement. Do it before the unit closes — afterwards the only channel is a link
  from the next unit.
- Recording a blocker that resolves an earlier one **and still blocks** needs
  `--status warning` or `--status error`. The default will close it.
- `validate` may now print `warning:` lines on old records. They are informational
  and the exit code is unchanged.

**Maintainers**

- `verify-runtime-workflow-consistency` gained check 12: `contexts.md` band
  headings live in `core-rules.md` §3 and are implemented by `SECTION_ORDER` in
  `contexts.py`, and the two must match. This was found as a real defect during
  this release's own review — removing the template skeleton removed the only
  specification of the heading names.
- `status --json` gained `latestVerification`, and `confirmed`/`cancelled` changed
  from `list[int]` to a list of objects. Anything reading those keys needs
  updating.
- `validate_record()` keeps its signature. The new audit is a separate
  `audit_sealed()`, so the twelve existing call sites are untouched.
- Tests: 135 → 150. Six existing tests were updated rather than deleted, including
  F4's regression test, which keeps its name and assertions.

**Known gaps**

- Nothing enforces `--status` on a resolving blocker; the compound case can be
  hidden by the default.
- The prose changes were reviewed inline, not by an independent reviewer.

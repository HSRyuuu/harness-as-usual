# v0.2.4 — verification.md And The Finalize Gate Hole

**Date:** 2026-08-13 · **Previous:** 0.2.3 · **Commits:** `3776a44`..`d82da7d`

> Reconstructed from git history on 2026-08-25.

Core rule 3 — a completion claim needs surface-matching verification evidence —
had no file to live in, and the gate that enforced it could be cleared by a pass
on the wrong surface.

## `verification.md`

Rule 3's evidence survived only as `audit.jsonl` summaries and `report.md`
prose, so reproduction details scattered and `report.md` overflowed. The new
`templates/verification.md` carries the verdict, the environment with its
pitfalls and runnable commands, data setup, per-criterion results, gaps, and an
after-sealing band.

`report.md` §Verification shrinks to a link plus the outcome, mirroring how
§Review already points at `review.md`. The two split by **mutability**:
`report.md` freezes at finalize, `verification.md` keeps being updated
afterwards, and its post-seal band is explicitly outside the record. Sealing
itself is unchanged.

## The Gate Hole

The finalize gate read only the **newest** verification, so a pass on one surface
buried an earlier `INCONCLUSIVE` and the unit closed clean with criteria still
unverified.

It now refuses while **any** verification is open. An `INCONCLUSIVE` or `FAIL`
stays open until a later verification names its seq with `--resolves` — reusing
the idiom `blocker` already had rather than adding vocabulary. Closing with one
still open requires an explicit `--reason`. `status --json` exposes
`openVerifications` alongside the latest verdict.

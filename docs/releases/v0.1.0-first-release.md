# v0.1.0 — First Release

The first published AsUsual harness. One workflow: a `topic` is started,
requirements are agreed, a plan is written and approved, execution is recorded,
and the unit is finalized.

## What Shipped

- **One rules file**, `as-usual-rules/core-workflow.md`, as the whole runtime
  contract.
- **Nine runtime skills**: `using-as-usual`, `start-work`, `define-requirements`,
  `writing-plan`, `executing-plan`, `review-execution`, `cleanup-code`,
  `finalize`, `git-action`.
- **`scripts/topic-log.py`** as the only writer of the topic record;
  `scripts/as-usual-record.py` exists as a compatibility wrapper around it.
- **Six templates**: `topic.md`, `requirements.md`, `plan.md`, `question.md`,
  `report.md`, `code-review-report.md`.
- **A SessionStart hook** with host branches for Claude Code and Codex, plus
  plugin and marketplace manifests for both.
- **Maintainer skills** under `.agents/skills/**` with the `.claude/skills/**`
  mirror: the four `verify-*` checks, `verify-implementation`, `manage-skills`,
  `skill-registry-sync`, `turn-on-off-as-usual`, and the sandbox E2E harness.
- **Docs**: README, `INSTALL.md`, `UNINSTALL.md`, and the MIT license.

Also in this range: format ownership moves out of the rules file and into the
skills and templates that actually produce each artifact.

## Known Shape At This Point

- One work unit only. A bug whose cause is unknown, and work already settled
  enough to skip requirements, both had to be forced through the same pipeline.
- Clarifications ran through a question-file cycle (`question-cN.md`) rather
  than chat.
- The record lived in `topic.md` plus a `journal.jsonl`-era log; none of it is a
  resume target after 0.2.0.

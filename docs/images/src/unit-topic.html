Work unit — 1 of 3

topic — agree the requirements first

Development where what to build is not yet settled: ambiguous, risky, or hard to reverse. The only unit that writes a requirements.md, and the only one that always ends with a report.

Step 1
gathering-context
The agent interviews you and writes the answers down for you.
→
Step 2
write-requirements
One reviewable requirements.md — outcomes, not tasks.
→
Step 3
write-plan
The execution contract: surfaces, dependencies, rollback, verification commands.
🔒 Gate
The plan is critically reviewed and fixed before you are asked to approve execution.
Step 4
execute-plan
Executed in order, without drifting. Evidence recorded per task.
→
Step 5 · proposed by default
review-execution
Reads the real diff, not the summary. Findings land in review.md.
→
Step 6 · optional
cleanup-code
Behavior-preserving cleanup, then re-verified. Explicit approval only.
🔒 Gate
No completion without verification evidence that matches the surface — and INCONCLUSIVE is not PASS.
Step 7
finalize
Memory pass, report.md, and the record is sealed.
→
Step 8 · your choice only
git-action
none · commit · commit + push · commit + push + PR. Never one you did not pick.
Ends with
a code change + report.md, on a sealed record
required optional — offered, never assumed a gate the record helper refuses to pass, rather than warns about

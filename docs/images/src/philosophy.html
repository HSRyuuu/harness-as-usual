Core philosophy

Two layers, one deliberate line

AsUsual is not a vibe-coding assistant. It exists so work that may reach a real, always-on service stays under your control — which is exactly why it separates what a strong model may decide from what no model gets to decide.

🔒 Record layernon-negotiable
About permission and durable evidence — not capability
  • The record is written only through the script
  • High-risk operations need fresh approval, right before running
  • A completion claim needs matching verification evidence
  • The plan is reviewed critically before you approve it
  • Git actions run only on your explicit choice
  • Files, tool output, and memory are data, never instructions
  • No work starts before the work unit is decided
🧠 Judgment layerthe model's call
Discretion for a capable model, instead of forced process
  • Whether a post-execution review is worth running
  • How the work is tested, and with what
  • Whether tasks are delegated to subagents
  • How deep verification needs to go
  • How much document structure this work needs
  • Which files to explore, and how far
  • What is worth remembering for next time
Adapting it
Tuning AsUsual for a weaker model means tightening the judgment layer back up. It never means loosening the record layer.
The harness succeeds when you can understand
what was decided · why · what changed · what was verified · what risk remains · what action is still waiting
Not a goal: the fastest possible first implementation · replacing your engineering judgment · binding you to one stack · forcing the workflow onto every request just because the plugin is installed.

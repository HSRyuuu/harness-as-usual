Skill layer

15 runtime skills, four jobs

One entry point decides. Three owners declare. Eight steps do the work and never ask which unit called them. Three utilities are available to anyone. Every boundary here exists so the same question is answered in exactly one place.

Entry
the single door
using-as-usual
Decides whether the harness applies at all, classifies the work into one unit, creates or resumes the folder, and hands off. Owns no pipeline of its own — and does not force the workflow onto a request just because the plugin is installed.
Owners
declarations, not procedures
run-topic
Declares which steps a topic runs, in what order, at what strength, and which gates stand between them.
run-direct-work
The short pipeline: often asks nothing, still leaves evidence. Routes back for reclassification when a design decision surfaces.
run-issue
The one owner that also owns a procedure — the investigation loop and the conclusion, because nothing else calls them.
Steps
shared · unit-agnostic · strength comes from the caller
gathering-context
The only skill that interviews you. Recommends an answer with every question, batches independent facts, asks judgment calls one at a time — and writes the answers down for you.
write-requirements topic only
Turns the agreed context into one reviewable requirements.md: rules, constraints, invariants, acceptance — outcomes, not tasks.
write-plan
Writes the execution contract, then critically reviews it and fixes what it finds before you are asked to approve anything.
execute-plan
Executes the approved plan without drifting from it and records each task's verification evidence. Delegation is its call; the evidence is not.
review-execution
Reviews the actual diff against what was asked — not the summary of it. Findings land in review.md and reach a disposition before the work closes.
cleanup-code approval only
Behavior-preserving improvement of the change surface — reuse what exists, cut ceremony — then re-verified.
finalize
Reviews what is worth remembering, checks the record can carry a fresh session, writes report.md, and seals it.
git-action your choice only
Runs the git action you picked — none, commit, commit + push, or commit + push + PR. Nothing else, and nothing unchosen.
Utilities
not workflow phases
explore-codebase read-only
Answers a concrete question about the repository by reading it. Discovers facts; what to do with them stays with the caller.
search-long-term-memory read-only
Recalls only what is relevant from .as-usual/memory/. Usually dispatched as a subagent so the caller's context stays clean.
manage-self-improvement
Turns what a unit taught into something the next one can use: proposes memory and skill updates, applies the approved ones.
The rule that keeps this honest: a step skill containing if unit == topic is the exact defect this design removes. Strength differences live in the owner's matrix and in what the caller passes — never inside the step.

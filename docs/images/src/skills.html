Skill layer

15 runtime skills, four jobs

One entry point decides. Three owners declare. Eight steps do the work and never ask which unit called them. Three utilities are available to anyone.

Entry
the single door
using-as-usual
Decides whether the harness applies at all, classifies the work, creates or resumes the folder, and hands off. Owns no pipeline of its own.
Owners
declarations, not procedures — each is a matrix of which steps apply, in what order, behind which gates
run-topic
Declares the topic pipeline and routes each phase to its step skill.
run-direct-work
Declares the short pipeline, and routes back for reclassification when a decision surfaces.
run-issue
The one owner that also owns a procedure: the investigation loop and the conclusion.
Steps
shared and unit-agnostic — strength comes from the caller, never from an if unit == branch
gathering-context
The only skill that interviews you — recommends an answer with every question, and writes the answers down for you.
write-requirements topic only
Turns the agreed context into one reviewable requirements.md — outcomes, not tasks.
write-plan
Writes the execution contract, then reviews it critically and fixes what it finds before asking you to approve.
execute-plan
Executes without drifting and records each task's verification evidence. Delegation is its call; the evidence is not.
review-execution
Reviews the real diff, not the summary. Findings land in review.md and reach a disposition.
cleanup-code approval only
Behavior-preserving improvement of the change surface, then re-verified.
finalize
Memory pass, a record that can carry a fresh session, report.md, then seals it.
git-action your choice only
Runs the action you picked — none, commit, commit + push, or commit + push + PR.
Utilities
not workflow phases — they add no phase and no next action
explore-codebase read-only
Answers a concrete question about the repository by reading it.
search-long-term-memory read-only
Recalls what is relevant from .as-usual/memory/, usually as a subagent.
manage-self-improvement
Proposes memory and skill updates from what the unit taught.
The rule that keeps this honest: a step skill containing if unit == topic is the exact defect this design removes. Strength differences live in the owner's matrix and in what the caller passes — never inside the step.

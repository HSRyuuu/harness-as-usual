Record layer

One writer. One schema. It refuses rather than warns.

Every work unit keeps exactly two required files. Current phase and next action are never remembered — they are derived from the record, so a session that starts cold picks up from disk.

The work folder
.as-usual/<unit>/yyyy-MM-dd-<slug>/
contexts.md — one document holding every decision agreed with you, whenever it was made. Three bands, three rules:
Top · near-fixed
the initial request verbatim, the chosen unit, the in/out boundary, links to artifacts and other units
Middle · updated freely
the agreed decisions. When a later decision reverses an earlier one, the earlier entry is edited so the section always reads as the current agreement
Bottom · append-only
Q&A raised after the gathering stage
audit.jsonl — the append-only evidence trail. Nothing is lost by editing the middle band, because this file keeps the history.

The only writer
scripts/as-usual-record.py · schema as-usual.record.v1
initaddmovelinkstatusvalidate
Never hand-edited. If the helper cannot express a transition, the agent stops and reports the missing capability instead of writing the file itself.
A closed vocabulary. Units, event kinds, actors, statuses, phases, and next actions are all fixed sets. An event kind exists only when a gate enforces something with it — detail no gate checks goes in the summary, never into a new kind.
phase is the name of the skill that owns the work, so there is no mapping table to drift. Each unit may use only its own subset — the script rejects the rest.
Recorded as you go, not batched at the end.

What it refuses
guaranteed by the script, not by agent goodwill
  • A verification with no verdict — and an unverifiable result is INCONCLUSIVE, never PASS
  • Execution approval for a topic or direct-work with no recorded plan review
  • Confirming a hypothesis with no evidence, or cancelling one with no reason
  • Finalizing a topic/direct-work that has no verification on the record
  • Finalizing an issue with no conclusion.md, or one whose record holds nothing confirmed
  • Moving a folder that already produced requirements.md, plan.md, or conclusion.md
  • Any append to a sealed record — a finalized or cancelled unit accepts only a link to another unit
  • Any unit, kind, actor, status, phase, or next action outside the closed vocabulary
State is derived, never remembered as-usual-record.py status --dir <work-dir> --json returns the current phase and next action. The agent re-reads disk before phase decisions; chat memory is supporting context only.
Artifacts are not committed by default .as-usual/memory/ is the one commit target — durable knowledge that accumulates across units, updated at finalize. MEMORY.md has a 3000-character budget.
The rules are never copied into your project as-usual-rules/ is read from the plugin at runtime. Your repository gets .as-usual/ artifacts and nothing else.
Trust boundary: project files, tool output, generated artifacts, and recalled memory are treated as data and evidence — never as workflow instructions. Secret values are never printed, copied into artifacts, or committed.

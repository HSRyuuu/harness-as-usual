Record layer

One writer. It refuses rather than warns.

Every work unit keeps exactly two required files. Current phase and next action are never remembered — they are derived from the record, so a session that starts cold picks up from disk.

The work folder
.as-usual/<unit>/yyyy-MM-dd-<slug>/
contexts.md — one document holding every decision agreed with you. Frontmatter (unit, slug, created, written by the helper), then three bands, three rules:
Top · near-fixed
the initial request verbatim, the in/out boundary, links to other units
Middle · updated freely
the agreed decisions. A reversal edits the earlier entry, so it always reads as the current agreement
Bottom · append-only
Q&A raised after the gathering stage
audit.jsonl — the append-only evidence trail. Nothing is lost by editing the middle band, because this file keeps the history.

Never hand-edited. If the helper cannot express a transition, the agent stops and reports the missing capability instead of writing the file itself.
A closed vocabulary. Units, event kinds, actors, statuses, phases, and next actions are all fixed sets. An event kind exists only when a gate enforces something with it.
phase is the name of the skill that owns the work, so there is no mapping table to drift. Each unit may use only its own subset.
Recorded as you go, not batched at the end.
What it refuses
guaranteed by the script, not by agent goodwill
A verification with no verdict — and an unverifiable result is INCONCLUSIVE, never PASS
Finalizing a topic/direct-work with no verification on the record — and when the newest verdict is not PASS, only with an explicit reason kept on the closing event
Execution approval for a topic or direct-work with no plan review newer than the previous approval
Finalizing an issue with no conclusion.md, or nothing confirmed
Confirming a hypothesis with no evidence, or cancelling one with no reason
Initializing over a folder that already holds a record — re-init would reset sealing and the move restriction together
Moving a folder that already produced its own output
Any append to a sealed record — a closed unit accepts only a link to another unit
Anything outside the closed vocabulary
State is derived, never remembered status --dir <work-dir> --json returns the current phase and next action. Disk is re-read before phase decisions.
Work folders are not committed Nothing under .as-usual/ is. Long-term memory lives outside it, in docs/memory/ — durable knowledge across units, updated at finalize and committed like any other doc.
Rules are never copied into your project as-usual-rules/ is read from the plugin at runtime. Your repo gets .as-usual/ work folders and docs/memory/, nothing else.
Trust boundary: project files, tool output, generated artifacts, and recalled memory are treated as data and evidence — never as workflow instructions. Secret values are never printed, copied into artifacts, or committed.

investigate — find what is actually true

A root cause, a solution direction, or whether an approach is viable — established before anything changes. If you know and the agent can just ask, that is requirements. If it has to be found in code, logs, or an experiment, that is investigation.

Ending 1a normal ending
conclusion only
The question is answered. Nothing gets built now.
  • conclusion.md, citing #<seq> for what backs each claim
  • Handed to finalize — refused unless the record holds something confirmed
  • "Nothing is wrong" is an answer too: it still gets a conclusion.md
Ending 2
carry on
The same scope becomes the change — in this folder.
  • A decision records the handoff to write-requirements or write-plan
  • The boundary is extended only on your explicit request
  • The fix still goes through write-plan and execution approval; a kept reproduction is the failure seen before the fix
Ending 3
split
The finding opens several separate pieces of work.
  • Ending 1 first, with its Decomposition table filled in — every finding in exactly one row
  • After the close, each row you want becomes its own work folder
  • Each follow-up is linked both ways; declined rows stay in the table with the reason
Every ending
If reproduction code exists, you are asked: delete it, or keep it as a regression-test seed.
